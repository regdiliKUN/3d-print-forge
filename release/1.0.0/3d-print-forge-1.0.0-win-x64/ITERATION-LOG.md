# 机型预设功能 · 迭代记录

> 对象：3D Print Forge「打印机型参数预设 + 参数建议」模块
> 基线：机型预设功能首次交付版（20 款机型、机型主卡、三步骤引导、打包到 `I:\PrinterApp`）
> 本轮：22 轮迭代，每轮聚焦至少一个质量维度，均有自检
> 结果：单元测试 262 → **296 项全通过**；全按钮实测 **23/23**；包体已同步重建

---

## 一、逐轮记录

### 第 1 轮 · 正确性 —— 提升「官方实测」覆盖率

- **目标**：`verified` 标记只有 3 款机型可信，其余 17 款用户不知道该信多少。
- **改动**：按 Anycubic 官方《水洗树脂 2.0 推荐参数表》逐项比对，把 P1 / M7 Max / M7 Pro 的抬升、熄灯、底曝与官方值核对一致后提级为"官方"，并写入 `official_exposure`。
- **理由**：官方参数表是厂家在真机上实测标定的，可信度高于任何推算。之前只是没去核对。
- **自检**：官方机型 3 → **4**；带 `official_exposure` 的机型 1 → **4**。

### 第 2 轮 · 完整性 —— 统一 FDM 的层高区间

- **目标**：光固化预设都有 `layer_range`，FDM 没有，层高只受 `nozzle*0.2~0.75` 硬编码夹取。
- **改动**：`_fdm()` 增加由喷嘴推导的 `layer_range`；FDM 分支改用该区间。
- **理由**：同一件事（层高边界）原有两个来源，改一处忘一处就会不一致。
- **自检**：`bambu_x1c` 输出 `layer_range=[0.08, 0.3]`，与喷嘴 0.4 的 0.2/0.75 倍一致。

### 第 3 轮 · 正确性 —— 预设库导入即自检

- **目标**：20 款机型是手写数据，写错不会立刻报错，只会在某次建议里给出离谱数值。
- **改动**：新增 `validate_presets()`，校验区间合法性、正数约束、层高上限是否超过喷嘴、别名/默认项是否指向存在的机型；`_validate_on_import()` 在模块导入时执行，失败直接抛错。
- **理由**：数据错等于代码错，必须 fail-fast，而不是带着脏数据跑。
- **自检**：注入 5 类坏数据（区间反转、照度为零、层高超喷嘴、喷嘴为零、流量为零），**全部被捕获**；正常库 0 问题。
- **踩坑**：校验函数必须放在 `PRESETS` / `ALIASES` / `DEFAULT_PRESET` 都定义之后，否则导入时 `NameError`。

### 第 4 轮 · 性能 —— 消除重复切片

- **目标**：`_geometry` 里悬垂分析和轮廓积分各自切了一遍同一张网格。
- **改动**：`support_analysis()` / `cross_section_profile()` 增加可选 `sections` 参数，`_geometry` 只切一次给两处共用。
- **理由**：纯浪费。
- **自检**：93.9ms → **68.0ms（−28%）**；悬垂比完全一致，体积积分反而更接近真实体积（采样 20 → 48）。

### 第 5 轮 · 正确性 —— 层高取整可能越界

- **目标**：`clamp` 后再 `round`，取整本身会把值推出区间（`hi=0.298`、步长 0.01 → 0.30 > hi）。
- **改动**：新增 `_round_in_range()`：夹取 → 取整 → 再夹取；步长为 0 不除零；区间倒置时取更细一侧。
- **理由**：切片器拿到超出机型上限的层高会直接拒绝，用户还以为是我们算错了。
- **自检**：6 个边界用例（hi 越界、lo 越界、正常、低于下限、区间倒置、零步长）**全部落在合法区间**。

### 第 6 轮 · 完整性 —— 喷嘴可选

- **目标**：预设声明了 `nozzle_options` 却没有任何入口；换 0.6 喷嘴时层高、壁数、线宽、流量全不变。
- **改动**：`recommend` 接受 `nozzle` 覆盖，在算层高之前落到 printer 上，层高区间按新喷嘴重算；不支持的值取最近规格并提示。
- **理由**：换喷嘴是 FDM 最常见的操作之一，参数必须整条链跟着动。
- **自检**：0.4/0.6/0.8 均正确生效；0.5 回退到 0.4 并给出可选清单；真实网格下 0.4→0.6 时长 **1.09h → 0.93h**，壁厚 0.4→0.8 时 1.2→1.6mm。

### 第 7 轮 · 完整性 —— 材料可选

- **目标**：材料是建议链的源头（决定层高上限、曝光、温度），却完全写死。
- **改动**：新增 `GET /api/materials`；前端在机型主卡里加材料选择条，切换后旧建议立即作废。
- **理由**：同一个模型用标准树脂和韧性树脂，曝光差 40%。
- **自检**：材料条 4 项正常渲染；切到韧性树脂后曝光 **3.4s → 4.7s**，建议确实重新生成。

### 第 8 轮 · 一致性 —— 材料名称收敛到单一来源

- **目标**：前端 `MATERIAL_LABEL` 和后端材料表各存一份，必然漂移。
- **改动**：删除前端硬编码表，改为 `materialName()` 从 `/api/materials` 取。
- **理由**：两处维护同一份事实，改一处就会不一致。
- **自检**：`grep MATERIAL_LABEL` 无残留；界面显示与后端一致。

### 第 9 轮 · 边界情况 —— 超出成型空间必须阻断

- **目标**：旧逻辑只对"最大边超限"给警告，且放不下时仍照常给出可打印参数。
- **改动**：新增 `_fits_build()`，排序后逐轴比较（等价于允许任意 90° 旋转），超限则 `feasible=False`。
- **理由**：用户很可能直接照参数去切，必须阻断而不是提醒。
- **自检**：4 个用例全部正确，包括"最大边没超但轴交换后放不下"（290 进不了 285.5）。

### 第 10 轮 · 边界情况 —— 细节小于分辨率

- **目标**：最薄处小于 2 个像素（光固化）或小于喷嘴（FDM）时，"打出来糊了"是最常见的事故，但没有任何提示。
- **改动**：按工艺分别用像素/喷嘴判定并给出建议加厚值。
- **理由**：这是可预期、可预防的失败。
- **自检**：SLA 0.03mm 触发像素提示；FDM 0.30mm 触发喷嘴提示；FDM 2.0mm 不误报。
- **连带修复**：发现 `_clean_wall` 把 <0.05mm 一律当伪影丢弃，导致**真实薄壁反而无法提示**。改为区分"孤立尖峰"（用 5% 分位数剔除）与"整片都薄"（保留并提示）。4 种分布场景复验全部正确。

### 第 11 轮 · 性能 —— 网格与截面缓存

- **目标**：每次调建议都重读模型、重切 48 层截面，而换方案/换材料时模型根本没变。
- **改动**：加 `_load_mesh_cached`（按 path+mtime+size）与 `_sections_cached`，FIFO 淘汰 3 个。
- **理由**：实测 1MB/2 万面 STL 单次加载 44ms、切 48 层 88ms，用户在方案间来回切就一直在付这个钱。
- **自检**：首次 1782ms → 同参数重算 **17ms**，换方案 **16ms**，换材料 **16ms**（约 105×）；几何量与结果一致性校验通过。

### 第 12 轮 · 正确性 —— 厂家标定值参与计算

- **目标**：`official_exposure` 之前只做展示，没参与计算——最可信的数据被浪费了。
- **改动**：有官方值的组合以官方值为锚点，按 `exp(adh·Δ层高/Dp)` 只做层高外推；同时把纯物理结果作为交叉校验写进理由。
- **理由**：实测标定 > 公式反解，锚点法既用上实测值又保留了物理外推能力。
- **自检**：P1 Max + 水洗树脂 → **2.0s**（即官方值）；理由里如实标注"纯物理会给出 2.45s，两者差 22%"。

### 第 13 轮 · 一致性 —— 机型按项目记忆

- **目标**：机型存在全局 `localStorage`，一个工作台里有多台机器时会张冠李戴。
- **改动**：改为 `tpf_printer:<pid>` 优先、全局兜底；载入项目时恢复并同步材料清单。
- **理由**：项目与机型是一对一关系，全局记忆是错的抽象。
- **自检**：代码路径确认；`loadProject` 中恢复 + 重载材料，不会出现"树脂机型配线材"。

### 第 14 轮 · 可读性 —— 抽出 `_resolve_nozzle`

- **目标**：第 6 轮把 18 行喷嘴逻辑内联进了 `recommend`，主函数变长且难以单测。
- **改动**：抽成独立函数，只负责"请求值 → 机型支持值"的归一化并返回提示。
- **理由**：`recommend` 已经有 200+ 行，不该再塞分支。
- **自检**：抽取后行为完全一致（0.4/0.6/0.8/0.5 四组结果与抽取前相同）。

### 第 15 轮 · 边界情况 —— 退化模型

- **目标**：0.1mm 立方、空网格、零体积薄片都报"可行、0 耗材"，语义错误。
- **改动**：新增退化判定（无三角面 / 体积 < 0.01mm³ / Z 向无厚度 / 比一层还矮），`feasible=False` 并严重扣分。
- **理由**：给出"正常参数"比报错更危险。
- **自检**：4 类退化输入全部 `feasible=False`；正常件仍 `True`。

### 第 16 轮 · 完整性 —— 界面呈现阻断态

- **目标**：后端从第 9/15 轮起能判"不可打印"，但界面完全不显示——能力有、出口没有。
- **改动**：新增红色阻断条说明具体原因；`应用参数` 按钮禁用，`applyAdvice` 内再加一层兜底。
- **理由**：后端结论必须让用户看见，否则等于没做。
- **自检**：400mm 模型 → 阻断条出现，文案含具体超限值；应用按钮 `disabled=true`；`applyAdvice` 被调用时也会拒绝。

### 第 17 轮 · 完整性 —— 导出跟随用户选择

- **目标**：切片器配置导出永远用默认机型，用户选了 Mars 4 也导出 P1 Max 的参数。
- **改动**：下载接口接受 `printer/material/nozzle/plan`；导出体补 `printer_preset` 全量、`feasible`、`uncertainty`、`confidence`。
- **理由**：导出的价值就是"拿去切片器照着填"，机型不对等于白导。
- **自检**：默认 → P1 Max；指定 Mars 4 + 韧性 → **Mars 4、曝光 5.5s**；指定 X1C + 0.6 喷嘴 → 层高 0.2。导出字段 12 个齐全。
- **踩坑**：第一次替换因"对齐/对应"一字之差静默失败，靠回归测试才发现——说明"替换成功"必须验证而不是假设。

### 第 18 轮 · 一致性 —— API 错误语义

- **目标**：未知机型只回 `404 没有这个机型预设`，不告诉调用方有哪些可用。
- **改动**：404 体带 `available`（全部 key）、`aliases`（旧别名）、`hint`。
- **理由**：排错成本。
- **自检**：`/api/printers/not_exist` → 404 + 20 个可用 key + 5 个别名；旧别名 `sla_mid` 仍返回 200。

### 第 19 轮 · 可读性 —— 文案与单位统一

- **目标**：界面出现 `2.3 s1.8–2.8s` 这种数值与区间粘连；层高恰好等于标定层高时仍说"外推"。
- **改动**：区间改为 `P10–P90：1.8–2.8s` 并加间距；锚点文案按"是否真的外推"分支。
- **理由**：读起来像 bug 的文案会削弱整份建议的可信度。
- **自检**：层高 0.05 时文案变为"厂家在 0.05mm 层高下标定为 2s，与当前层高一致，直接采用"。

### 第 20 轮 · 可测试性 —— 用测试锁住新行为

- **目标**：22 轮改动横跨数据、物理、边界、接口，没有测试就会被后续改动悄悄回退。
- **改动**：新增 `tests/test_printer_presets.py`（34 项），覆盖预设自检、别名、机型和材料联动、官方锚点、喷嘴级联、层高必在区间、取整边界、超尺寸、轴交换、退化模型、薄壁与伪影区分、缓存一致性、材料接口、404 载荷、导出跟随、标定隔离。
- **理由**：测试是把"这一轮的推理"变成"以后不会退回去"的唯一手段。
- **自检**：**34 项一次通过**；全量 262 → **296 项全通过**。

### 第 21 轮 · 可访问性 —— 选择器键盘导航

- **目标**：机型列表只能鼠标点，键盘只能"回车选第一条"，列表一长就不可用。
- **改动**：`↑↓` 移动光标、`Home/End` 跳首尾、`Enter` 选中；光标态与 hover 视觉区分。
- **理由**：键盘可达性是基础体验，不是加分项。
- **自检**：↓1 次→P1 Max，↓3 次→M7 Max，↑→P1，End→GKtwo，Home→P1 Max，Enter 正确选中并关闭。

### 第 22 轮 · 一致性 —— 全链路复核，修掉自相矛盾

- **目标**：把 22 轮的改动放在一起跑，看有没有互相打架。
- **改动**：发现"不可打印 + 置信度高"矛盾，补齐 `feasible=False` 的置信度扣分（−0.30）。
- **理由**：单点都对、合起来矛盾，是迭代最容易漏的失败模式。
- **自检**：全按钮 **23/23 通过、零 JS 错误**；超尺寸件置信度 0.81 → **0.05（低）** 并列出原因；包体同步后独立启动验证通过。

## 二、最终版本相对初始版本的整体提升

| 维度 | 初始版本 | 最终版本 |
|---|---|---|
| 预设数据可信度 | 3 款标官方，1 款有官方曝光 | **4 款官方**，4 款带官方曝光锚点；导入自检 0 问题 |
| 数据校验 | 无，写错只能靠人眼 | 导入即校验，5 类注入错误全部捕获 |
| 机型联动 | 只影响成型空间/照度 | 机型 + **材料** + **喷嘴** 三者联动，全链路重算 |
| 曝光算法 | 纯物理反解 | **厂家标定优先**、物理外推兜底、两者交叉校验 |
| 层高合法性 | 可能越界/为 0 | 6 类边界全部落在合法区间 |
| 不可打印识别 | 仅"最大边超限"警告 | 超尺寸（含轴交换）+ 退化模型 + 低于分辨率，**界面红色阻断并禁用应用** |
| 壁厚判定 | 一律丢弃 <0.05mm | 区分孤立伪影与真实薄壁，真实薄壁能正确警告 |
| 建议耗时 | 每次重算 | 首次 1782ms → **重算 16ms**（约 105×） |
| 导出 | 固定默认机型 | 跟随用户选择，含机型全量 + 置信度 + 可行性 |
| 接口语义 | 404 无信息 | 404 带可用清单与别名 |
| 键盘可达性 | 仅回车选第一条 | ↑↓/Home/End/Enter 完整导航 |
| 前后端一致性 | 材料名两处维护 | 单一来源（后端） |
| 测试 | 262 项 | **296 项**（新增 34 项覆盖本轮全部行为） |

### 关键判据保持稳定

- 悬垂判据 7 例：立方体/圆锥/宽柱承接 → 可选；细柱/球/四角柱大板 → 需要（未因迭代漂移）
- 三档方案层高单调、`sources` 恰好 3 组、PETG 喷头 240℃ 等既有硬断言全部保持

### 未被改动（有意为之）

- 核心结构：`printers.py` 预设库 + `advisor` 建议引擎 + `/api/printers` 接口 + 机型主卡 UI，分层未变
- 未引入新依赖、未改动既有 API 契约（仅新增可选查询参数）
- 未为了"凑轮数"做纯格式调整；每一轮都对应一个可验证的问题
