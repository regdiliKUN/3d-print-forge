# 3D Print Forge

> English documentation: [README.en.md](README.en.md)

从导入 STL 到产出可打印成品的一站式处理工具集。分步向导、七项模型体检、自动修复、镂空打孔、支撑生成、参数建议、批量处理，全部在一个本地 Web 界面里完成。

## 快速开始

```bash
# 1. 建环境（首次）
python -m venv .venv
.venv/Scripts/python.exe -m pip install numpy scipy trimesh fastapi "uvicorn[standard]" \
    python-multipart rtree networkx psutil manifold3d fast-simplification \
    scikit-image mapbox-earcut triangle httpx pytest

# 2. 启动
.venv/Scripts/python.exe run.py        # → http://127.0.0.1:8000
```

把 STL 拖进浏览器窗口即可。原文件不会被改动，所有操作都作用在工作副本上。

Docker 方式：

```bash
docker compose up --build      # → http://127.0.0.1:8000
```

容器内监听 `0.0.0.0`，`data/` 挂载到宿主机，重建镜像不丢项目。

## 上手引导

第一次打开且没有任何项目时，会自动弹一个 6 步引导（可跳过，记在 localStorage 里不再打扰）。
已有项目时不会弹——用过的人不该再被挡一次。

- **示例模型**：导入页有「加载示例模型」，生成一个故意带破洞、薄壁、碎屑、法线反转的样件，
  点一下就能把检测、修复、热力图、支撑这些功能全走一遍，不用自己去找 STL。
- **帮助面板**：右上角 `?` 或直接按 `?` 键，列出全部快捷键；里面还有「重新看引导」。
- **空状态引导**：项目列表为空时不是干巴巴一句「没有模型」，而是给出三步具体动作。
- **参数说明**：每个输入框下方的灰字就是该参数的取值建议和常见坑。
- **侧栏流程进度**：五个任务（导入 / 检测 / 修复 / 处理 / 导出）自动打勾，点任务直接跳到对应步骤。
- **一键走完**：侧栏「一键走完剩余步骤」会按 检测 → 修复 → 处理 串行执行，中途失败会明确停下并说明原因。
- **建议一键应用**：建议页的「应用到处理页」把壳厚、支撑、镂空这几项直接写进处理参数并跳转。

## 六步流程

| 步骤 | 做什么 | 为什么必须在这一步 |
|---|---|---|
| 导入 | 建立工作副本 | 后续全部操作可回退 |
| 检测 | 七项体检 | 先看清问题全貌，避免修一处坏一处 |
| 修复 | 补洞/法线/碎屑/自交 | 布尔运算要求输入是闭合流形 |
| 处理 | 减面/镂空/打孔/支撑/摆正 | 先摆正再打孔，否则孔会跟着旋转跑到侧面 |
| 建议 | 材料/层高/填充/温度 | 每条建议都从几何量推出，附推导依据 |
| 导出 | STL/配置/报告/日志 | 配置可存成模板供批量复用 |

## 新功能

- **分件**：按最长边自动等分成多块，切面自动封盖，导出 zip；每块给出切面质心，提示加定位桩的位置。
- **版本对比**：量化「导入时」与「当前」的面数、体积、表面积变化和顶点位移。拓扑变了会明确提示「位移只能说明改了多少，不能说明哪里改厚了」。
- **历史回滚**：操作历史里任意一步都能「回到这版」，随时退回导入态。
- **3MF 导出**：保留单位和多体结构，比 STL 更适合现代切片软件。
- **拼盘排版**：多个模型按行式装箱排到一块平台上，放不下的单独列出原因，导出合并 STL。
- **HTML 报告**：自包含单文件（样式内联、无外部资源、无脚本），直接发给同事或存档。
- **英寸识别**：254mm 恰好是 10 英寸、203.2mm 是 8 英寸——这类从英制 CAD 转来的件会被标为「提示」而不是「正常」，避免比例错但数值看着对的情况被漏掉。
- **手动支撑点选**：点「开启点选」后直接在模型表面点击加支撑点，绿色小球标出位置，点完切到「手动点选」执行。手动点不会被「贴平台」或「下方有实体」的自动过滤挡掉。
- **撤销**：`Ctrl+Z` 或历史区的「撤销一步」，逐级退回。会跳过 revert 记录本身，连续撤销不会来回弹。
- **快速预设**：手办（光固化）/ FDM 功能件 / 快速验证三套参数组合，一键套用后仍可逐项微调。
- **参数模板**：把当前处理参数存成模板，处理页下拉即可套用。
- **姿态微调**：X/Y/Z 各 ±90° 步进旋转，转完自动落到平台。
- **切片参数配置**：导出对齐常见切片器字段的 JSON，含层高、曝光、温度、支撑、耗材估算。
- **批量 CSV**：批量结果导出成带 BOM 的 CSV，Excel 直接打开不乱码。
- **模型库**：收藏（星标优先排序）、标签、按名称/标签搜索、重命名。
- **平台机型预设**：拼盘时直接选 Mono X / Mars 3 / Sonic Mini / FDM 220 等，自动填平台尺寸。
- **层高对比**：同一模型换 0.03/0.05/0.08/0.1mm 的层数与耗时对照。
- **批量打包**：勾选多个模型打包成 zip，附 manifest.json。
- **布尔运算**：两个模型之间做并集 / 差集 / 交集（manifold 引擎），结果写回工作副本。
- **模型合并**：不做布尔，直接把多件拼成一个网格。
- **多格式导出**：STL / 3MF / OBJ / PLY 四种格式。
- **重做**：`Ctrl+Y` 或 `Ctrl+Shift+Z`，撤销后能回去。
- **依赖锁定**：`requirements.lock` 固定全部版本，复现环境不用赌。
- **项目复制**：克隆一个项目，同一个源文件、独立的处理历史。
- **模板导入导出**：参数模板存成 JSON，换机器或分享给同事直接导入（同名自动加后缀不覆盖）。
- **孔位避薄壁**：排液孔会自动避开壁厚不足的位置，找不到合适位置时明确报错而不是打出豁口。
- **打印记录**：每件可记「打成功 / 打失败 + 备注」，累计成功率和最近 30 条记录，用来判断这套参数到底靠不靠谱。
- **支撑点 CSV**：手动点选的支撑点可导出成 CSV，也能从 CSV 导入（兼容逗号/分号/空格分隔，自动跳过表头）。
- **标签筛选**：点项目列表里的标签直接按该标签过滤。
- **任意平面切割**：输入法向量 + 位置百分比沿任意方向切开，保留侧写回当前项目、另一侧另存新项目（体积守恒）。
- **手动挖孔**：点模型表面确定孔位，按指定孔径/深度布尔挖孔，深度 0 表示穿透。
- **项目打包迁移**：导出含模型 + 历史的 zip，换机器导入即可继续；导入时拦截 `../` 等 zip slip 路径。
- **精确尺寸缩放**：填目标宽/深/高，可等比（以最大值为准）或三轴独立；缩完自动落平台。
- **平台居中**：一键把 XY 中心对齐原点、Z 底面贴 0。
- **打印队列**：把多个项目排进待打队列，支持上移/下移/移出，重复加入自动去重。
- **层耗时估算**：按截面积折算每层耗时（曝光 + 抬升 + 扫描），给出总层数和总时长。
- **装配预览**：分件后按切割位置把各块摆回去、分色显示，确认装配关系和有没有干涉。
- **任意角度旋转**：除 90° 步进外，可输入任意角度（含负数）。
- **批量打标签**：勾选多个项目一次追加标签。
- **数据清理**：`python tools/cleanup.py` 列出无人引用的产出文件，`--apply` 才真删（默认干跑）。
- **参数变更对比**：列出每一步改了哪些参数、从多少改到多少，只对比两次都出现过的键。
- **分件间隙检查**：各块摆回原位后两两求交，重叠体积 > 0.5mm³ 就报干涉。

## 检测项与修复动作

| 检测项 | 判定依据 | 对应修复 |
|---|---|---|
| 水密性 | 每条边是否恰好被两个面共享 | `fill_holes` 边界环 + 耳切三角化 |
| 法线方向 | 有向体积符号、退化面计数 | `fix_normals` 统一朝向 |
| 壁厚 | 沿面法线反向射线打穿到对侧 | `thicken` 体素外扩 |
| 非流形边 | 被 3 个以上面共享的边 | `merge_vertices` |
| 自相交 | 11 轴 SAT + 近共面排除 | `resolve_self_intersection` 体素重网格 |
| 孤立面片 | 按共享顶点做连通分量 | `remove_small` 保留主体 |
| 单位尺寸 | 包围盒量级 + 25.4 整数倍匹配 | `rescale` 按因子换算 |

## 实现上踩过的坑

这些不是理论问题，是实测中真实踩到并修掉的：

- **`trimesh.repair.fill_holes` 会静默失败**。在多数破损模型上直接返回 `False` 且什么都不做，即使装了 `mapbox-earcut`。所以补洞是自己实现的：提边界边 → 串成有向环 → 耳切定拓扑 → 内部细分加点 → 按洞口一环邻居拟合二次曲面、把补面抬到贴合原曲率 → 固定边界的拉普拉斯平滑（GPU 加速）。旧版「投影到平面后直接耳切」在曲面上会补出一块塌陷的平板，既有明显折痕又会把洞口附近网格拽变形；新版实测相邻补面夹角从 63° 降到 4°，最长补边缩短约 40%。
- **marching cubes 的内腔朝向不确定**，取决于体素索引顺序。用体积符号判定，内腔必须贡献负体积，否则镂空后体积会变成「外壳+内腔」反而变大。
- **模型填满自己包围盒时 marching cubes 直接报错**（薄板、立方体都是），因为 grid 全为 True 找不到 0/1 交界面。栅格化时四周补一圈空体素解决。
- **SAT 判自交不能只看「有重叠」**。三角形是零厚度面片，共面相邻时法线方向投影必然重叠，体素网格上会把上万对相邻面误判成自交。改为排除近共面的对。
- **内腔不能用减面压面数**。`fast_simplification` 在体素网格上做边折叠必然产生非流形边，内腔一旦非流形，打孔布尔运算就崩。改用体素 2× 降采样，面数降 74%，拓扑天然保持。
- **「贴平台的底面」不是悬垂**。否则一个平放的立方体会被判成需要支撑。

## 性能与调度

- **流式加载**：二进制 STL 用 `np.memmap` 按 20 万面分块读，块间只保留顶点与索引；ASCII STL 逐行流式解析。
- **顶点焊接**：STL 每个三角形存独立顶点，加载后按量化坐标去重，否则无法判断流形性。
- **并发与闸门**：任务队列按 `max_workers` 起工作线程；每个任务开跑前检查进程内存，超过 `memory_limit_mb` 就排队等待而不是硬跑导致 OOM。
- **GPU**：探测 cupy / torch，都没有就明确显示「CPU 模式」，不假装有加速。补洞的拉普拉斯平滑与点投影在 GPU 上跑（`app/gpu.py` 统一封装，显存/后端异常自动退回 numpy）。安装见 `requirements-gpu.txt`（`cupy-cuda12x[ctk]`，需连 CUDA 头文件一起装，否则只能探测到卡却编不了内核）。
- **修复后复检**：修复完成立刻用 `analysis.analyze_mesh` 复跑全套检测并清空旧建议，避免「勾了全部选项、修完还提示不水密」这种状态不同步。
- **断点续跑**：修复任务每步把中间结果落盘到任务临时目录，中断后重跑加载中间结果而不是从头算。

### 环境变量

不改配置文件也能覆盖，适合部署：

```bash
TPF_MAX_WORKERS=4          # 并发任务数
TPF_THREAD_WORKERS=8       # 单任务线程数
TPF_MEMORY_LIMIT_MB=8192   # 进程内存上限
TPF_VRAM_LIMIT_MB=0        # 显存上限，0 不限
TPF_CHUNK_FACES=200000     # 流式加载分块
TPF_PREVIEW_FACES=60000    # 预览网格上限
TPF_WALL_WARN=0.8          # 壁厚告警线（mm）
TPF_WALL_FAIL=0.4          # 壁厚失败线（mm）
TPF_OVERHANG_DEG=45        # 悬垂角阈值
```

每个请求都带 `X-Trace-Id` 响应头，日志里按同一个 id 能串起整条链路。

## 性能基准

`.venv/Scripts/python.exe tests/bench.py`，2 万面模型（20,480 面）：

| 阶段 | 耗时 | 内存增量 |
|---|---|---|
| 二进制 STL 加载 | 24 ms | 1.2 MB |
| ASCII STL 加载 | 85 ms | 0.5 MB |
| 检测（7 项，默认参数） | **684 ms** | 2.8 MB |
| 壁厚全量 6000 采样（无截断） | 20,995 ms | 20.1 MB |
| 壁厚全量 6000 采样（截断 12mm） | **1,303 ms** | 1.7 MB |
| 补洞 | 10 ms | 0.2 MB |
| 镂空 2mm | 882 ms | 5.5 MB |
| 自动摆放（6 候选） | 13 ms | 2.6 MB |

壁厚扫描最初用 `trimesh` 的 ray，会对「射线数 × 三角形数」做全量 AABB 矩阵——6000×20480 就是 1.2 亿个 float64，**内存冲到 4.7 GB、耗时 46 秒**。改成 rtree 索引取候选 + Möller–Trumbore 精确求交 + 射线长度截断后，降到 1.3 秒 / 20 MB。

## 优化记录

22 轮迭代，每轮都有可证伪的测试：

| # | 方向 | 改动 | 效果 |
|---|---|---|---|
| 1 | 正确性 | 壁厚多方向采样（法线 ±20°） | 曲面/楔形处不再高估 |

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 镂空报「模型不水密」 | 有开放边 | 回「修复」跑补洞 + 统一法线，复检通过再处理 |
| 打孔布尔运算失败 | 输入非流形 | 先跑「体素重网格消解自交」再做镂空 |
| 检测很慢 | 大模型 + 高采样 | 调低壁厚采样面数；厚模型会自动走粗筛快速通道 |
| 内存持续上涨 | 缓存累积 | 降低 `TPF_MEMORY_LIMIT_MB`，缓存会按预算自动释放 |
| 3D 预览空白 | 本地 three.js 缺失且拿不到 CDN | 仓库已内置 `static/vendor/three.module.min.js`；缺失时其余功能不受影响，补回该文件即可离线预览 |
| 任务卡在「等待内存资源」 | 进程占用超过上限 | 等前序任务结束，或调高上限 / 减少并发 |

## 已知限制

- 补洞按「洞口一环邻居」拟合二次曲面来顺曲率，对常见的球面/柱面/自由曲面效果很好；但极度扭曲、跨越多条棱线的洞仍可能补得不理想，需要回到建模软件处理。
- GPU 加速只覆盖补洞的平滑/投影等向量化算子；体素重网格（消解自交/加厚）仍是 CPU 实现，超大网格会偏慢。
- 体素法操作（镂空/加厚/重网格）会让锐边轻微圆化，精度受 pitch 限制。重网格/加厚重建后会补一遍 Taubin λ|μ 平滑，抹掉 marching cubes 的台阶纹（实测相邻面夹角波动降低约一半、体积基本不变），代价是极锐的棱会再圆一点。
- 自交检测用 KD 树取局部候选对，理论上是近似检测——但实际模型的自交都是局部的。
- 支撑是直柱，没有树状支撑和接触点细化，复杂件仍建议在切片软件里再调。
- 3D 预览优先用内置的 `static/vendor/three.module.min.js`，只有该文件缺失时才回退 CDN；两种来源都拿不到时降级成提示文字，其余功能不受影响。
