# 3D Print Forge

从导入 STL 到产出可打印成品的一站式处理工具集。分步向导、七项模型体检、自动修复、镂空打孔、支撑生成、参数建议、批量处理，全部在一个本地 Web 界面里完成。

## 快速开始

```bash
# 1. 建环境（首次）
python -m venv .venv
.venv/Scripts/python.exe -m pip install numpy scipy trimesh fastapi "uvicorn[standard]" \
    python-multipart rtree networkx psutil manifold3d fast-simplification \
    scikit-image mapbox-earcut triangle httpx pytest

# 2. 启动
.venv/Scripts/python.exe run.py        # → http://127.0.0.1:8000
```

把 STL 拖进浏览器窗口即可。原文件不会被改动，所有操作都作用在工作副本上。

## 六步流程

| 步骤 | 做什么 | 为什么必须在这一步 |
|---|---|---|
| 导入 | 建立工作副本 | 后续全部操作可回退 |
| 检测 | 七项体检 | 先看清问题全貌，避免修一处坏一处 |
| 修复 | 补洞/法线/碎屑/自交 | 布尔运算要求输入是闭合流形 |
| 处理 | 减面/镂空/打孔/支撑/摆正 | 先摆正再打孔，否则孔会跟着旋转跑到侧面 |
| 建议 | 材料/层高/填充/温度 | 每条建议都从几何量推出，附推导依据 |
| 导出 | STL/配置/报告/日志 | 配置可存成模板供批量复用 |

## 检测项与修复动作

| 检测项 | 判定依据 | 对应修复 |
|---|---|---|
| 水密性 | 每条边是否恰好被两个面共享 | `fill_holes` 边界环 + 耳切三角化 |
| 法线方向 | 有向体积符号、退化面计数 | `fix_normals` 统一朝向 |
| 壁厚 | 沿面法线反向射线打穿到对侧 | `thicken` 体素外扩 |
| 非流形边 | 被 3 个以上面共享的边 | `merge_vertices` |
| 自相交 | 11 轴 SAT + 近共面排除 | `resolve_self_intersection` 体素重网格 |
| 孤立面片 | 按共享顶点做连通分量 | `remove_small` 保留主体 |
| 单位尺寸 | 包围盒量级 + 25.4 整数倍匹配 | `rescale` 按因子换算 |

## 实现上踩过的坑

这些不是理论问题，是实测中真实踩到并修掉的：

- **`trimesh.repair.fill_holes` 会静默失败**。在多数破损模型上直接返回 `False` 且什么都不做，即使装了 `mapbox-earcut`。所以补洞是自己实现的：提边界边 → 串成有向环 → Newell 法线定平面 → 投影后耳切三角化 → 按法线同向补面。
- **marching cubes 的内腔朝向不确定**，取决于体素索引顺序。用体积符号判定，内腔必须贡献负体积，否则镂空后体积会变成「外壳+内腔」反而变大。
- **模型填满自己包围盒时 marching cubes 直接报错**（薄板、立方体都是），因为 grid 全为 True 找不到 0/1 交界面。栅格化时四周补一圈空体素解决。
- **SAT 判自交不能只看「有重叠」**。三角形是零厚度面片，共面相邻时法线方向投影必然重叠，体素网格上会把上万对相邻面误判成自交。改为排除近共面的对。
- **内腔不能用减面压面数**。`fast_simplification` 在体素网格上做边折叠必然产生非流形边，内腔一旦非流形，打孔布尔运算就崩。改用体素 2× 降采样，面数降 74%，拓扑天然保持。
- **「贴平台的底面」不是悬垂**。否则一个平放的立方体会被判成需要支撑。

## 性能与调度

- **流式加载**：二进制 STL 用 `np.memmap` 按 20 万面分块读，块间只保留顶点与索引；ASCII STL 逐行流式解析。
- **顶点焊接**：STL 每个三角形存独立顶点，加载后按量化坐标去重，否则无法判断流形性。
- **并发与闸门**：任务队列按 `max_workers` 起工作线程；每个任务开跑前检查进程内存，超过 `memory_limit_mb` 就排队等待而不是硬跑导致 OOM。
- **GPU**：探测 cupy / torch，都没有就明确显示「CPU 模式」，不假装有加速。
- **断点续跑**：修复任务每步把中间结果落盘到任务临时目录，中断后重跑加载中间结果而不是从头算。

## API

```
POST /api/upload                       导入（multipart，支持多文件）
GET  /api/projects                     项目列表
GET  /api/projects/{id}                项目详情（含检测报告）
POST /api/projects/{id}/analyze        检测        → job
POST /api/projects/{id}/repair         修复        → job
POST /api/projects/{id}/process        处理        → job
GET  /api/projects/{id}/advice         参数建议
GET  /api/projects/{id}/mesh           预览网格（base64 顶点/索引）
GET  /api/projects/{id}/download       ?kind=stl|config|report|log
GET  /api/jobs                         任务列表
POST /api/jobs/{id}/pause|resume|cancel
POST /api/batch                        批量处理
GET  /api/templates                    参数模板
GET  /api/system/resources             实时 CPU/内存/GPU
GET  /api/workflow                     向导步骤与参数释义
GET  /api/logs?lines=120               最近日志（带 trace id）
```

### 环境变量

不改配置文件也能覆盖，适合部署：

```bash
TPF_MAX_WORKERS=4          # 并发任务数
TPF_THREAD_WORKERS=8       # 单任务线程数
TPF_MEMORY_LIMIT_MB=8192   # 进程内存上限
TPF_VRAM_LIMIT_MB=0        # 显存上限，0 不限
TPF_CHUNK_FACES=200000     # 流式加载分块
TPF_PREVIEW_FACES=60000    # 预览网格上限
TPF_WALL_WARN=0.8          # 壁厚告警线（mm）
TPF_WALL_FAIL=0.4          # 壁厚失败线（mm）
TPF_OVERHANG_DEG=45        # 悬垂角阈值
```

每个请求都带 `X-Trace-Id` 响应头，日志里按同一个 id 能串起整条链路。

## 实测效果

用同一个模型（破损球体 + 圆锥，1343 面，43495 mm³）跑完整流程：

| 阶段 | 结果 |
|---|---|
| 检测 | 7 项，2 项严重（9 条开放边、法线整体朝内） |
| 修复 | 开放边 9 → 0，有向体积 -43445 → +44895，碎屑清除 |
| 处理 | 镂空省料 80.3%，打 2 个 φ3mm 排液孔，110 根支撑，自动摆正到「绕 X-90°」 |
| 体积 | 43495 mm³ → 5546 mm³ |
| 导出 | 15,950 面 STL，落在平台（zmin = 0），可回读 |

## 性能基准

`.venv/Scripts/python.exe tests/bench.py`，2 万面模型（20,480 面）：

| 阶段 | 耗时 | 内存增量 |
|---|---|---|
| 二进制 STL 加载 | 24 ms | 1.2 MB |
| ASCII STL 加载 | 85 ms | 0.5 MB |
| 检测（7 项，默认参数） | **684 ms** | 2.8 MB |
| 壁厚全量 6000 采样（无截断） | 20,995 ms | 20.1 MB |
| 壁厚全量 6000 采样（截断 12mm） | **1,303 ms** | 1.7 MB |
| 补洞 | 10 ms | 0.2 MB |
| 镂空 2mm | 882 ms | 5.5 MB |
| 自动摆放（6 候选） | 13 ms | 2.6 MB |

壁厚扫描最初用 `trimesh` 的 ray，会对「射线数 × 三角形数」做全量 AABB 矩阵——6000×20480 就是 1.2 亿个 float64，**内存冲到 4.7 GB、耗时 46 秒**。改成 rtree 索引取候选 + Möller–Trumbore 精确求交 + 射线长度截断后，降到 1.3 秒 / 20 MB。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 镂空报「模型不水密」 | 有开放边 | 回「修复」跑补洞 + 统一法线，复检通过再处理 |
| 打孔布尔运算失败 | 输入非流形 | 先跑「体素重网格消解自交」再做镂空 |
| 检测很慢 | 大模型 + 高采样 | 调低壁厚采样面数；厚模型会自动走粗筛快速通道 |
| 内存持续上涨 | 缓存累积 | 降低 `TPF_MEMORY_LIMIT_MB`，缓存会按预算自动释放 |
| 3D 预览空白 | 离线环境拿不到 CDN | 其余功能不受影响；要离线预览可把 three.js 放到 `static/vendor/` |
| 任务卡在「等待内存资源」 | 进程占用超过上限 | 等前序任务结束，或调高上限 / 减少并发 |

## 已知限制

- 补洞的耳切三角化要求洞口近似平面。极度扭曲的洞会补出不好的面，需要回到建模软件处理。
- 体素法操作（镂空/加厚/重网格）会让锐边轻微圆化，精度受 pitch 限制。
- 自交检测用 KD 树取局部候选对，理论上是近似检测——但实际模型的自交都是局部的。
- 支撑是直柱，没有树状支撑和接触点细化，复杂件仍建议在切片软件里再调。
- 3D 预览从 CDN 加载 Three.js，离线环境会降级成提示文字，其余功能不受影响。
